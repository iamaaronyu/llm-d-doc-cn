# llm-d 路由器

**llm-d 路由器**是 llm-d 技术栈中推理请求的智能入口。它在不重新实现全功能网络代理的前提下，提供精细的 LLM 感知负载均衡、请求排队和策略执行。

## 组成 {#composition}

llm-d 路由器由两个主要功能部分组成：

### 代理（Proxy） {#proxy}

任何符合规范的工业级 L7 代理。代理负责数据面，包括连接管理、TLS 终止和请求转发。支持的实现范围广泛，既包括自行管理的应用负载均衡器（例如 Istio、agentgateway、Envoy AI Gateway），也包括符合规范的云托管服务，例如 Google Cloud 的应用负载均衡器。

请参阅[**代理深入解析**](proxy.md)，了解部署模式（独立模式与网关模式）、请求流程以及 Gateway API 集成。

### llm-d 端点选择器（EPP） {#llm-d-endpoint-picker-epp}

代理在处理每个请求时都会咨询的专门服务。[EPP](epp/README.md) 承载了路由的“智能”，利用来自模型服务器的实时信号做出最优放置决策。

请参阅[**llm-d EPP 深入解析**](epp/README.md)，了解路由引擎的架构、插件流水线（过滤器、打分器、选择器）以及流量控制机制。

## 工作原理 {#how-it-works}

当推理请求到达代理时，代理会“暂存”该请求，并通过 `ext-proc`（External Processing，外部处理）协议回调 EPP。

EPP 根据 [InferencePool](../inferencepool.md) 的当前状态评估该请求——考虑 KV 缓存局部性、当前负载和优先级等因素——并把最优模型服务器 Pod 的地址返回给代理。然后，代理把原始请求转发到该目标。

这种解耦架构使 llm-d 能够利用生产级代理的性能和可靠性，同时为 LLM 专用的路由逻辑提供高度可扩展的框架。

## 术语 {#terminology}

为了在整个项目中保持表述清晰，我们使用以下标准术语：

- **llm-d 路由器（llm-d Router）**：完整的智能入口，包括**代理**和**端点选择器（EPP）**。在所有语境中都用该术语取代“Router”。
- **llm-d 端点选择器（llm-d Endpoint Picker，EPP）**：实现路由智能和打分逻辑的具体组件。当指代 EPP 本身特有的能力或配置（而不是整个请求路由系统）时使用该术语。
- **推理网关（Inference Gateway）**：在**网关模式**下运行时 **llm-d 路由器**的同义词。
- **请求调度器（Request Scheduler）**：EPP 内的一个子组件，作为智能请求路由的核心决策引擎，对候选模型服务器（即端点）进行过滤和打分。
