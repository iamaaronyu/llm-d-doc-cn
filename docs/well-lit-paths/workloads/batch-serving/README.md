# 批处理服务

**批处理服务**工作负载类别定义了在 llm-d 基础设施上处理大规模、离线或对延迟不敏感任务的推荐整体部署方案。

根据你的集成需求、规模和运维环境，llm-d 为基于队列的推理和批量推理提供两条不同的路径：

- **[批处理网关](batch-gateway.md)**：企业级、全托管的**兼容 OpenAI 的 Batch API**（`/v1/batches`、`/v1/files`）。最适合多租户环境，即客户端需要正式的异步作业提交、文件存储、状态跟踪，并严格区分交互式与批处理计算资源。
- **[异步处理](asynchronous-processing.md)**：轻量级、低开销的队列分发机制（使用 Redis 或 GCP Pub/Sub）。最适合需要低复杂度后台任务处理的内部微服务架构，或通过动态分发门控来填充推理资源池中的“闲置”容量。

部署选项、对比分析和运维指南请参阅[批处理服务指南](https://github.com/llm-d/llm-d/tree/v0.10.0/guides/batch-serving)。
